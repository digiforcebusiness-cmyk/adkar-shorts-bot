## Describe your API client and its use case

> Adkar Shorts Bot is a personal automation tool with a single user: me, the
> owner of the YouTube channel @ZainKhairAllahChannel. It is not distributed and
> is not offered to anyone else.
>
> The tool generates short vertical videos containing Arabic Islamic
> supplications (adkar) rendered as text on a plain background, with a
> synthesized ambient audio track. All content in the videos is generated by the
> application itself; no third-party audio, video, or imagery is used.
>
> Once per day, a scheduled job selects a supplication that has not been used
> recently, renders it into a 1080x1920 video, and uploads it to my own channel
> using `videos.insert`. The application performs no other API calls.

## Which YouTube API Services do you use, and why?

> Only the YouTube Data API v3, and only the `videos.insert` endpoint.
>
> I request the single scope `youtube.upload`, which permits uploading to my own
> channel and nothing else. I deliberately do not request `youtube.force-ssl` or
> `youtube`, because the application has no need to read, edit, or delete any
> video. An earlier version requested `force-ssl` in order to post a comment on
> its own uploads; that feature was removed and the scope dropped with it.

## How many users does your API client have?

> One — me. The application is not distributed, has no sign-up, and no other
> person can authenticate with it.

## What data do you store, and for how long?

> The OAuth client ID, client secret, and refresh token are stored as encrypted
> GitHub Actions secrets. The YouTube video IDs of the application's own uploads
> are stored in a file in the source repository, solely so that the same
> supplication is not published twice.
>
> No data belonging to any other YouTube user is accessed or stored. There is no
> database, no server, no analytics, and no sharing with third parties.

## Do you use the API to access data belonging to other users?

> No. The application only ever uploads to the authenticated owner's own
> channel. It reads nothing.

## Estimated daily quota usage

> 10,000 default daily units. I am not requesting a quota increase — I am
> requesting compliance approval so that uploaded videos are not restricted to

## Demo video

The audit asks for a video showing the API in use. It does not need production
value; it needs to demonstrate honestly what the application does. Screen
recording with narration or on-screen captions is fine. Aim for 2–4 minutes.

Suggested sequence:

1. **Show the OAuth consent screen.** Run the authorization flow and pause on
   the consent dialog so the requested scope is legible. Say aloud that the only
   scope requested is `youtube.upload`.
2. **Show the code that calls the API.** Open `src/adkar_bot/youtube.py` and show
   `upload_video`. Point out that `videos.insert` is the only endpoint called.
3. **Show a render.** Run `py -3 -m adkar_bot.cli render` and play the resulting
   MP4 from `output/`. State that the text, background and audio are all
   generated by the application, with no third-party content.
4. **Show an upload.** Run `py -3 -m adkar_bot.cli publish`, then show the video
   appearing in YouTube Studio. Note that it arrives private because the project
   is not yet audited — this is the restriction you are asking to lift.
5. **Show the schedule.** Open `.github/workflows/publish.yml` and the Actions
   run history, to show it runs once per day unattended.
6. **State the scale plainly.** One user, one channel, one upload per day.

Upload the demo as an **unlisted** video and paste the link into the form.

## Publishing the privacy policy

The form requires a publicly reachable privacy policy URL. `PRIVACY.md` in the
repository root is written and ready. Two ways to publish it:

**Option A — make the repository public** (simplest, and gives you a homepage
URL too). The repository contains no secrets: `.env` and `client_secret*.json`
are gitignored and were never committed. Verify before flipping:

```
git log --all --full-history -- .env "client_secret*.json"
```

Empty output means neither was ever committed. Then:

```
gh repo edit --visibility public --accept-visibility-change-consequences
```

Enable Pages under Settings → Pages → deploy from branch, and the policy is at
`https://digiforcebusiness-cmyk.github.io/adkar-shorts-bot/PRIVACY`.

**Option B — keep the repository private and publish a Gist.** GitHub Pages on a
private repository requires a paid plan; a public Gist is free:

```
gh gist create PRIVACY.md --public --desc "Adkar Shorts Bot privacy policy"
```

The command prints the Gist URL. Use that in the form.

## Realistic expectations

- Review typically takes weeks, and follow-up questions are normal.
- Answer follow-ups consistently with the code and the demo video. Contradiction
  between the three is what stalls audits.
- A single-user personal tool is a legitimate use case, but it is unusual for
  this form, which is mostly used by commercial products seeking quota. Expect
  questions about why automation is needed at all; the honest answer is that
  the content is generated programmatically and published on a fixed schedule.
- The five videos already uploaded are permanently locked private. Approval does
  not retroactively unlock them; they would need re-uploading afterwards.
